# きっかけ 情報量 独立監査（minimal_information_design スキル準拠）

- 実施：2026-11-25、独立審査担当（作者の自己評価は参照していない。コードのみから判定）
- 対象：`MainActivity.kt` 全画面UI、`WidgetProvider.kt`、`Engine.kt` の通知・トースト文言、`Model.kt` のテンプレ定義（バッジ実態の確認用）
- 対象バージョン：v2.12.0（commit 2541191）時点
- 検証の性質：コードによる静的監査＝**仮判定**。人間の初見テスト（3秒／無読）は未実施

## 判定軸（コンセプト正本、2026-11-24 本人言語化）

「ショートカット系アプリに抵抗のある人が、フィードを眺めるだけで興味本位で色々試せるアプリ。なんとなく眺めて簡単に試せる体験が主役。作る（ウィザード）は二次導線。」

| 要素 | 内容 |
|---|---|
| 誰 | 自動化に抵抗のある人 |
| 場面 | なんとなく眺める |
| 行為 | 気になったものを軽く試す |
| 気持ち | 自分にもできた、という小さな成功 |
| 最優先価値 | 試すまでの摩擦の小ささ |

判定文の型：「これが無くなると、コンセプトの［要素］が成立しなくなる」。書けない項目は支援（助け先の必須を名指しできる場合）かノイズ。

## 数え方

- 要素＝利用者が「1つの意味のまとまり」として認識する単位。グループはグループで1つ。
- FeedCard は「型」として1枚分を数え、51枚の繰り返しは選択肢数として別記する。ウィザードのパラメータUIも「選択中のトリガー分だけ同時表示」のため型として数える。
- 背景の光・ガラス面などの質感は全画面共通で「背景」1要素として数える。

## 総括（先に結論）

- 全 **138項目**：必須 53／支援 76／ノイズ 9（無関係8＋阻害1）
- **全体ノイズ率 6.5%**（型ベース）。ただしフィード画面は **19%** で突出し、しかもノイズの実体であるバッジは **51枚中42枚のカードに出現** するため、「眺める」画面での実効ノイズは率以上に大きい。
- v2.8.0〜v2.12.0 の削減（カード最小化・色の意味づけ・設定集約）は効いている。残っているノイズは「バッジ」「常設化した案内文」「同じ注意書きの複数出現」「存在しない場所への案内文」に集中する。
