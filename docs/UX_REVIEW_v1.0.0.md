# UX見直し記録：きっかけ v1.0.0（concept-driven-ux スキル手順）

実施日：2026-11-16。範囲は見直しと改善案まで（実装は本人の選択待ち）。
進め方：コンセプト確認 → 機能ごとの評価 → 維持・変更・統合・削減の比較 → 独立審査（作成者の結論を渡さない分離入力） → 照合 → コンセプト最終照合。

## コンセプト（判断軸）
[スマホの操作を覚えるのが苦手な人] が [日常の小さな場面] で [3ステップで自動化を置く] ことで [「自分にも作れた」と感じ、スマホに任せられる安心を得る] 体験。
アート方針の核：一番見せたいもの＝自分の自動化が並ぶホーム／「自分にも作れた」／やらない雰囲気＝設定画面みたいな難しさ。

## 独立審査の判定：保留
骨格（3ステップ・色分け・全日本語・自動命名・テンプレ）はアート方針に忠実で合格水準。ただし体験の信頼性に関わる必須指摘5件があり、その解消で合格に転じうる、という判定。

## 指摘とディレクター判断（全件採用）

### 必須（v1.1で直す）
- UX-1 アプリ未選択でも保存でき、永遠に発火しない自動化が並ぶ → 必須パラメータ未選択時は保存不可にする
- UX-2 テスト実行が条件で止まると無反応（SPECの「全アクション即実行」とも矛盾） → テスト時は条件を外し、結果を必ず言葉で返す
- UX-3 約15分間隔チェックの遅延が電池・Wi-Fiで説明されていない（注記はアプリ起動の枝だけ） → 該当する全きっかけに、その場で遅延説明を出す
- UX-4 権限チェックがホーム最上部で主役を奪い、無関係な許可まで並べる → 「その許可が要る自動化がある時だけ」出し、一覧より下／折りたたみへ移す
- UX-5 発火を確認する手段がなく、初回の試し（権限必須テンプレ）が無言で失敗しうる → 実行履歴を追加。試しには許可の予告を入れる（または許可なしで成功が分かる構成に）

### 推奨（v1.1で合わせて直す候補）
- UX-6 保存完了のフィードバック（新規カードへのスクロール＋強調、テストへの誘導）
- UX-7 テンプレ追加のフィードバック・重複防止・育った後の格下げ
- UX-8 削除の取り消し（スナックバー）
- UX-9 カード内のチップと要約文の二重表示を整理
- UX-10 オンボーディングの試しを、選んだ困りごとに対応させる（電池→電池テンプレ）
- UX-11 状態を変える動作に「戻す」動作を用意（マナーモード解除、音量を下げる、明るさを戻す）
- UX-12 条件の定義（夜だけ＝21時〜6時）をUIに一言添える
- UX-13 「アプリを開く」の同名重複を文言で区別（きっかけ＝開いたら／やること＝起動する）
- UX-14 アプリ選択を独立シート化し、スクロールの競合を解消
- UX-15 通知許可の依頼を、最初の自動化を確認した後のタイミングへ
- UX-16 資料の同期（SPEC現行化、UIカタログへの全パーツ登録、アート方針へのダーク配色追加）

## パソパソ側の評価との照合
一致した点：UX-4（権限の出し方）、UX-3（遅延の正直表示）、UX-10（オンボーディングの物語）、UX-7（テンプレの手応え）、UX-9（カード整理）、UX-16のSPEC陳腐化。
独立審査が新たに捉えた点：UX-1（保存の検証穴）、UX-2（テストの無反応とSPEC矛盾）、UX-5（発火確認の不在＋試しの無言失敗）、UX-11（戻す手段の不在）、UX-12（条件定義の不在）。いずれもコード実読で裏取り済み。

## コンセプト達成の最終照合（独立審査の判定を採用）
- 3ステップで作れる：実現
- 誰でも作れる：部分的に実現（権限の壁、検証穴、二重スクロールが削る）
- 置くだけでスマホが動く：部分的に実現（遅延の無説明、発火確認の欠如）
- 一番見せたい＝自分の自動化のホーム：部分的に実現（権限セクションの位置）
- 「自分にも作れた」：部分的に実現（保存・テスト・初回発火の成功体験に可視化がない）
- やさしい／つながる／ブロック遊び：実現
- 一番やさしい（他製品比較）：未確認（比較資料なし）
- 人間が触っての体験確認：未実施（実機待ち行列）→ 効果は仮説として扱う
