# UX見直し v1.3.0（concept-driven-ux スキル・2回目）

実施日: 2026-11-17 ／ 対象版: v1.3.0（コミット 1682752）
手順: コンセプト軸評価 → 独立審査（作成者の結論を渡さない分離入力）→ 照合 → ディレクター判断

## 総合判定：保留（必須4件の解消で合格に転じうる）

前回（v1.0）の必須5件＋推奨11件は v1.1 で全件解消済みで、その解消は今回の審査でもコード上で再確認された。3ステップの骨格・役割色の一貫・ホームで一覧が主役の構造は Liquid Glass 化を経ても保たれている。一方、v1.2（パターン拡大）と v1.3（ガラス化）の変更が新しい必須指摘4件を生んだ。

## 必須指摘（UX2-1〜UX2-4）

- **UX2-1 声で知らせるの成功判定が実結果と連動していない**：Engine の SPEAK は TextToSpeech の初期化完了を待たず `anyOk = true` を立てる（コード確認済み）。TTS不在・初期化失敗でも「動いたよ ✓」と履歴が付く。メディアキー系（再生／停止・次の曲）も受け手が無ければ何も起きないが成功扱い。解消条件：発声開始をもって成功とし、失敗は失敗として返ること。少なくともテスト実行では声が出なかった場合に成功表示にしない。
- **UX2-2 おやすみモードを解除する手段がアプリ内にない**：DND_ON（通知フィルタ NONE）の対になる解除アクションが存在しない（Model.kt 確認済み）。SILENT_OFF は着信音モードを戻すだけで通知フィルタは戻らない。状態変更系で唯一、復帰手段のない動作。解消条件：おやすみモード解除アクションの追加、または状態と戻し方の提示。
- **UX2-3 Step2 の15種フラット一覧が「一番やさしい」と両立していない**：グループも区切りもなく1列。静かにする系3種（マナーモード／解除／おやすみ）の違いが detail 一文だけでは判別しにくい。解消条件：日本語グループ分け（音／画面／知らせる／その他）または「よく使う＋もっと見る」構造化と、静かにする系の違いが選択前に一目で分かる表現。
- **UX2-4 オンボーディングの試しが許可の壁で無言失敗しうる（前回からの残件）**：試しテンプレ2種とも許可必須の動作で構成され、試しの場面から許可への導線がない。解消条件：試しを置いた直後またはホーム初回表示で、必要な許可だけがその場で案内されること。または許可なしでも成功を確認できる動作を含む構成にすること。

## 推奨指摘（UX2-5〜UX2-12）

- **UX2-5 ガラス面上の読みやすさが未検証**：ライトで白55%面の下に色の光が透け、補助テキスト（13sp・薄インク）の実効コントラストが位置で変動。ダークは面10%・ふち下6%で面同士の分離が弱くなりうる。実機確認が必要（実機待ち行列の対象）。**パソパソ側の補足**：本人が採用した Simple Glass スキルの正本（読み物ガラス 58%／16%、ぼかし24px・彩度185%、ふち上75%）と現行実装（55%／10%）には数値のずれがある。直す場合は正本へ寄せる。
- **UX2-6 失敗した実行が履歴に残らない**：成功のみ記録。許可不足の不発に気づけない。解消条件：失敗も理由つきで履歴に残す。
- **UX2-7 テスト実行の部分成功が伝わらない**：一部が許可不足でも1つ動けば「動いたよ ✓」。解消条件：部分成功を結果に含める。
- **UX2-8 ホーム下部の配置と色の漂い**：自動化が増えると「最近の実行」が遠くなる。テンプレ見出しの紫は役割色（条件）の例外。解消条件：履歴を一覧の近くへ、見出し色を役割に合わせる。
- **UX2-9 「充電が終わったら」の名称と実挙動のずれ**：実挙動は「ケーブルを抜いたら」。解消条件：ラベルを実挙動の名称へ。
- **UX2-10 ヘッドホンの「有線のみ」がアプリ内に書かれていない**：detail に明記すること。
- **UX2-11 テンプレ「ヘッドホンで音楽スタート」とトグル挙動のずれ**：再生中に発火すると止まる。名称の整合または注意書き。
- **UX2-12 資料と実装の乖離が再発**：SPEC が v1.2.0 のまま（ガラス記述なし）、ART_DIRECTION の色表に旧記述（カード白 #FFFFFF 等）が残る、UI_CATALOG の現行形への更新不足。解消条件：3資料の現行化。

## ディレクター判断

独立審査の指摘は全件採用。パソパソ側の評価（おやすみモードの復帰手段なし、Simple Glass 正本との数値のずれ）も審査と一致・補完する。実装範囲は本人の選択待ち。実機確認が要る UX2-5 は実機待ち行列に置き、催促しない。

## v1.4.0 での解消記録（2026-11-17、本人が「必須＋推奨も全部」を選択）

- UX2-1 解消：SPEAK は TTS初期化＋発声完了（UtteranceProgressListener）まで待ち、声が出た時だけ成功。テスト実行とレシーバー実行はバックグラウンドスレッド化（goAsync／Dispatchers.IO）。メディアキー系は受け手の有無を判定できないためベストエフォートのまま（残存注意として記録）。
- UX2-2 解消：「おやすみモードを解除」（DND_OFF、通知フィルタを ALL に戻す）を追加。権限チェックの対象にも含めた。
- UX2-3 解消：Step2 を4グループ（知らせる／音／画面・ライト／その他）に構造化。「音」グループに静かにする系の違いの一言を追加。
- UX2-4 解消：オンボーディング最終ページに「あと1つだけ」カードを追加し、試しの自動化に必要な許可だけをその場で案内（設定画面へのボタンつき、戻ると再判定）。
- UX2-5 コード側対応：ガラス面を Simple Glass 正本の読み物ガラス数値へ（面 58%／16%、ふち上 75%、補助文字 #554D44／#D8CFC2）。実機での可読性確認は未確認のまま実機待ち行列に残す。
- UX2-6 解消：失敗した実行も理由つきで履歴に記録（条件に合わなかった／許可が足りない／動作できなかった）。
- UX2-7 解消：ExecResult に PARTIAL_OK を追加し、テスト結果で「一部の動作は許可が足りなくて動かなかった」を伝える。
- UX2-8 解消：最近の実行を一覧の直下へ移動。テンプレ見出しの色を紫→インクに変更。
- UX2-9 解消：きっかけ名を「ケーブルを抜いたら」に変更。
- UX2-10 解消：ヘッドホンの detail に「有線の」を明記。
- UX2-11 解消：テンプレ名を「ヘッドホンで音楽」に変更（スタートの約束を外した）。
- UX2-12 解消：SPEC を v1.4.0 に現行化、ART_DIRECTION を v2.1 に改訂（色表をガラス値へ統一）、UI_CATALOG を v1.4 に更新。
- 検証：ユニットテスト10件全合格（グループ所属・DND_OFF・名称整合の3件を追加）。デバッグビルド成功。
