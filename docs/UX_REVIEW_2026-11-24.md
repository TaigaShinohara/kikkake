# UX独立審査 2026-11-24（v2.6.0時点）

判定軸コンセプト（2026-11-24 本人明言）：「ショートカット系（自動化）アプリに抵抗のある人が、フィードを眺めるだけで、興味本位で色々試せるアプリ」
- 誰＝自動化に抵抗・苦手意識のある人／場面＝なんとなく眺める／行為＝気になったものを軽く試す／気持ち＝「自分にもできた」という小さな成功とワクワク／最優先価値＝試すまでの摩擦の小ささ

審査方法：独立審査者（作者の自己評価を見ない）が MainActivity.kt 全体・Model.kt・SPEC・ART_DIRECTION・ゴールデン6枚を読み取りのみで確認。実ユーザーデータは無く、離脱等の効果は推測、構造は事実。

## 致命的
- **C-1 正本のコンセプトが「作る人」向けのまま**：SPEC冒頭「3ステップで誰でも作れる」、ART_DIRECTION「一番見せたいもの：自分で作った自動化が並ぶホーム画面」。フィードがホームになった後も未更新で、判断が作り手方向へ回帰する構造的リスク。解消＝両文書のコンセプトを「眺めて試す体験」へ書き換え。
- **C-2 オンボーディング8ページがフィードの前にある**：page 3〜5はウィザードの作り方講義。スキップは13spの小テキスト。解消＝初回から1〜2アクションでフィードのカードが目に入る。作り方解説はフィード到達後か試し置き体験内へ。
- **C-3 「これを使う」が所有化＋権限手続き＋画面離脱の複合操作**：即 addMacro（恒常追加）→不足権限で PermGuideDialog→マイセットへ遷移。先頭カード群（見すぎストッパー＝使用状況アクセス、22時に静かに＝マナーモード＋設定変更、LINE声お知らせ＝通知リスナー）はいずれも設定画面へ飛ぶ重い許可が要る。解消＝(a)許可の要否が押す前にカードで分かる (b)許可不要は追加と同時にその場で体感 (c)許可が必要でもフィードへ戻る導線を手続きより先に提示。
- **C-4 追加しても「できた」がその場で起きない**：テンプレの大半は未来イベント発火。即時実行はマイセットのタイル内「テスト」（小テキスト）だけでフィードに導線なし。解消＝追加直後に「今すぐ試す」が主ボタンで提示され、声・通知・バイブ等をその場で体感できる。

## 重要
- **I-1 フィード31件が固定順の一列のみ**：場面タグのセクション分け・絞り込みなし。並びは開発側の追加順。解消＝場面別セクション＋「すぐ試せる（許可不要・即時）」を優先配置。
- **I-2 「こんな事も」13件が主列に混ざり威圧要素を含む**：JavaScript実行、座標直書き＋編集前提、{battery}{ai} 変数記法。解消＝編集前提・技術用語のテンプレは主列から分離し、主列の文言に座標・変数記法・言語名を出さない。
- **I-3 マイセットが管理コンソール化**：書き出し/読み込み（JSON）、AI設定（APIキー入力）、権限チェックの大面が同居し、追加直後の着地点で主役になっている。解消＝着地画面の主役は「追加したもの＋次を眺める導線」。書き出し/読み込み/AIキーは設定の奥へ。
- **I-4 遅延の注意書きが推しカードの第一印象を下げる**：「※約15分ごとにチェック…」がイチオシ先頭カードにも訴求文直下に付く。解消＝即時/遅延を欠点表示でなく期待値として（即時バッジ等）伝え、C-4のその場試行で補完。
- **I-5 バッジ体系のノイズ化**：イチオシ1／AI1／新入り8／こんな事も13／無印8。分類軸が混在し選別に使えない。解消＝利用者の選別軸（すぐ試せる／声が出る／夜用 等）で統一し付与率を絞る。

## 軽微
- M-1 用語の不統一（フィード／マイセット／テンプレ／自動化／おすすめ併存、「マイセット」の説明なし）
- M-2 導入文の「全31件」強調は量の負担に読める。カード密度もポストより高い
- M-3 タイル要約が記号と括弧の羅列で可読性が低い
- M-4 ウィザードの重さ（Step1は17種全列挙、Step3プレビューは横スクロールで切れる）

## 残すべき良い点
1. 色分けブロック（きっかけ＝ピンク／やること＝オレンジ／条件＝紫）が全画面で完全統一。「眺めるだけ」で仕組みが読める中核資産
2. テンプレのタイトルと note が「生活の場面＋体験」で書かれている（31件全件に note）
3. オンボーディングの「試し置き」（困りごと3択→ぴったりな1件を置く）と完了時の触覚。仕掛けは正しく、問題は順序（C-2）だけ

## ノイズ率（コンセプト軸の仕分け）
- フィード画面：10要素＝必須5／支援4／ノイズ1 → 10%（ノイズはカード上端のグラデ帯）
- マイセット画面：14要素＝必須4／支援7／ノイズ3 → 約21%（ノイズは書き出し／読み込み／AIキー設定）
- 合計：24要素中4件＝約17%。ただしノイズと「支援だが主役級に大きい要素」が、試した直後の着地画面に集中しているのが本質的な問題

## 総括
画面単体の作りは丁寧で言葉と色の基礎体力は高い。最大の問題は体験の順序と着地：(1)眺める前に8ページの講義 (2)試す行為が所有化＋権限手続きと一体化 (3)成功の体感が未来送り (4)着地先が管理画面。個別の文言修正ではなく導線の再設計で解く性質。
