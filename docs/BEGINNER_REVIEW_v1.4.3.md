# 初心者レビュー（v1.4.3）—「スマホ自動化が初めての人でも使えるか」

実施：2026-11-17。方法：全画面のコード（MainActivity.kt / Model.kt / Engine.kt）を、「自動化アプリ未経験・スマホ操作に自信がない人」が初めて触る前提で精査。前回の各レビュー（UX／Simple Glass／デザイン整備／オンボーディング）とは別観点＝**言葉の分かりやすさ・最初の成功体験・迷子ポイント**に絞る。

## 判定：保留

骨格は初心者向けに作られている（3ステップ、既定値あり、テンプレ、言い換えの努力）。ただし「作ったのに動かない／言っていることと違う」が起きる穴が残っており、初心者の最初の成功体験を壊しうる。必須5件＋推奨7件。

## 良い点（確認済み）
- 既定値がある（時刻22:00・通知を出す）ので、Step1で何も選ばなくても前に進める。
- 「マナーモード＝着信音を消すこと」のような言い換えが要所にある。
- 削除に「元に戻す」がある。テスト実行の結果を言葉で返す。
- 通知許可を求めるタイミングが「最初の自動化のあと」になっている。

## 必須（初心者が詰まる・誤解する）

### B-1 「通知を出す」「声で知らせる」の中身が分からない＆変えられない
- 実装（Engine.kt）：通知も声も文面は固定で「『（名前）』を実行しました」。
- 一方、選択肢の説明は「お知らせを表示する」「スマホが声でお知らせする」だけ。初心者は普通「自分の用件を通知してくれる（例：薬を飲む）」と期待する。実際に届くのは実行報告で、期待とずれる。
- 対策：説明に実際の文面を明記する（例「『○○を実行しました』と表示される」）。できれば通知の文面を書ける欄を足す。

### B-2 権限が要る自動化を作っても、その場で案内が出ない
- ウィザードで保存／ホームでテンプレ追加をしても、不足している許可の案内はホーム下部の「権限チェック」までスクロールしないと見えない。
- 初回の自動実行が許可不足で失敗しても、知らせは一瞬のトーストのみ（スマホがポケットの中なら見逃す）。あとは実行履歴を見に来ないと分からない。「作ったのに動かない＝このアプリは壊れている」という最初の失敗になる。
- オンボーディングには「試しの直後に不足許可だけ出す」仕組み（UX2-4）があるのに、通常の作成フローには無い。
- 対策：保存・追加の直後に、不足している許可だけをその場で案内する（オンボーディングと同じ部品を使う）。

### B-3 許可の設定画面で「何をするか」の説明がゼロ
- 「許可する」を押すと Android の設定画面（一覧）に飛ばされるが、そこで『きっかけ』を探してオンにする、という手順の説明がアプリ側に一切ない。
- 特に「マナーモードの許可」「使用状況へのアクセス」は一覧から自分でアプリを探す形式で、初心者が最も迷子になる場所。
- 対策：ボタンの近くに「開いた画面で『きっかけ』を選んでオンにしてね」の一言を足す（許可ごとに行き先の形が違うので、それぞれに）。

### B-4 オンボーディングの完了文が事実と違う
- 「あとで試す」を選んだ場合（何も置いていない）でも、完了画面に「最初の自動化が待ってる。あとはスマホにまかせよう。」と表示される（OnboardingScreen page 7、trialPlaced=false 分岐）。
- ホームに戻ると空っぽで、「待ってるって言われたのに何もない」と混乱する。
- 対策：試していない場合は「ホームのテンプレから、いつでも試せるよ」など事実に合う文面に分ける。

### B-5 使い方を見返す手段がない
- オンボーディングは1回きり。ホームには「使い方」やヘルプの入口がない。
- スキップした人・忘れた人は、3ステップの考え方を知る手段がない。
- 対策：ホームに「使い方」入口を置き、オンボーディングのステップ紹介（3ページ分）だけでも見返せるようにする。

## 推奨（あると初心者が楽になる）

### B-6 時刻えらびが探しにくく、分が4択しかない
- 時は横スクロールで24個のチップ、分は 0/15/30/45 のみ。「7時5分」「22時10分」が作れないし、目的の時を探すのにスクロールが要る。
- 対策：分を5分刻み（または1分刻みの入力）にする、または時計型ピッカーにする。

### B-7 アプリ選択に検索とアイコンがない
- 一覧は名前だけ・上限80件・五十音順スクロール。初心者はアプリを「アイコン」で覚えていることが多く、名前だけだと探しにくい。81件目以降のアプリは選べず、理由も表示されない。
- 対策：検索欄とアプリアイコンの表示、上限の緩和。

### B-8 「約15分遅れて動く」注意が、テンプレとカードにない
- 電池・Wi-Fi・アプリ起動の遅延注意はウィザードの中だけ。ホームのテンプレから入れた人には伝わらず、「電池が減ったのに動かない」と感じる。
- 対策：テンプレの説明と、該当する自動化のカードに一言添える。

### B-9 失敗理由「条件に合わなかった」が通じない
- 実行履歴の文面。初心者には「条件」が何のことか分からない。
- 対策：「平日だけ等の条件に合わなかったので」のように言い換える。

### B-10 カードのスイッチに言葉のラベルがない
- オン／オフの状態が色と位置だけ。初心者には「今ついているのか」が不安。
- 対策：「オン」「オフ」の小ラベルを添える。

### B-11 「Wi-Fi」きっかけの説明が循環している
- ラベル「Wi-Fi」・説明「Wi-Fiにつながったら」で、結局何が起きる場面か想像しにくい。
- 対策：「家のWi-Fiにつながったら」のような場面の一言を足す。

### B-12 テスト結果がトーストだけで消える
- 見逃すと結果が分からない（実行履歴には残るが、そこへの誘導がない）。
- 対策：テスト直後はカード付近か履歴への一言で残す。優先度は低め。
