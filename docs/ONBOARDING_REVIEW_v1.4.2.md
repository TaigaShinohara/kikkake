# オンボーディングスキルでの見直し v1.4.2

実施日: 2026-11-17 ／ 対象版: v1.4.2（コミット ace5a70）
基準: mobile_onboarding スキル v0.10.0（絶対ルール、4つの達成条件、「押したら、褒める」、ページ地図）
方法: 現行8ページを1ページずつ棚卸しし、主張・役割・反応を点検。人間の体験確認は未実施（未確認として残す）。

## ページ地図（現行）

| # | 役割 | 主張 | 判定 |
|---|---|---|---|
| 0 | フック | スマホの操作、覚えなくていい | 主張1つ ✓ |
| 1 | 選択 | どんなことで困ってる？（3択・逃げ道あり） | 形は ✓、反応が不足（OB-1/OB-4） |
| 2 | マッチ | 選んだ悩みへの解決＋「きっかけはぴったり」 | 映し返し不足（OB-3） |
| 3 | ステップ1 | きっかけを選ぶ | ✓（動詞見出し） |
| 4 | ステップ2 | やることを選ぶ | ✓ |
| 5 | ステップ3 | 保存するだけ | ✓ |
| 6 | 試し操作 | 試しに1つ置いてみよう（本物の操作・「あとで試す」あり） | 形は ✓、成功の返しが弱い（OB-1/OB-7） |
| 7 | 接続 | 準備できたよ（＋試し直後の許可案内） | 予告が弱い（OB-5） |

## 総合判定：保留（必須4件）

流れの骨格（フック→選択→マッチ→ステップ3→試し→接続）は王道どおりで、1ページ1主張・3択・質問と結果の分離・「あとで試す」の完了扱いも守れている。落ちるのは「反応」の層：押した時に返すものが、全体を通してほぼ無い。

## 指摘

### 必須
- **OB-1 「押したら、褒める」の3点セットが未実装**：スキルでは、意味のある押下にはアニメーション＋触覚が全段階で必須、称賛の文は中（悩み選択・試しの成功）と大（完了）で必須。現行はどのページにも触覚フィードバックが無く、称賛の文も無く、弾みの反応も無い（選択肢の色が変わるだけ）。特に ①悩み選択（中）②試し操作の成功（中〜大）③完了（大）の3か所は無反応。解消条件：Android の performHapticFeedback で段階に合った触覚を付け、中・大では具体的な称賛を1文返す。弾みは pressable 系の反応で足りる範囲でよい。
- **OB-2 進捗が「8本バー」で総数が丸見え**：スキルは窓ドット（同時に最大5つ、現在を中心に窓が動き、端は小さく、数字で総数を数えさせない）。現行は8本のバーが全ページ数を示し、「まだ8ページもある」という圧を作る。解消条件：窓ドット方式に変える（1ページ進むごとに必ず1つ動く）。
- **OB-3 マッチ宣言に「映し返し」が無い**：ぴったり感の正体は、選んだ選択肢の言葉をそのまま映して返されること。現行ページ2は解決策の提示（「22時に自動で静かにできるよ」）から入り、選んだ言葉（「夜に音が鳴って困る」）を受け止める文が無い。解消条件：ページ2の先頭に、選んだ言葉を受けた一文を置き、その後に宣言（ぴったり）と根拠1つ、の順にする。
- **OB-4 選択→マッチの遷移に余韻が無い**：現行は選択後400ミリ秒で自動遷移し、反応を読む間が無い。スキルの順序は、反応（250〜400ミリ秒）→余韻（タップから合計900〜1,200ミリ秒）→遷移→次のページは順番に入場。解消条件：称賛の文を現在のページで返し、合計900ミリ秒前後で遷移する。連打の二重遷移防止も併せて入れる。

### 推奨
- **OB-5 接続ページの予告が弱い**：「始める」の先で最初に何が起きるか（ホームに、置いた自動化が待っていること）を一言で予告する。現行の補足は抽象的。
- **OB-6 スキップと戻るの常置**：スキップはページ0と2にだけあり、他ページには無い。戻る導線もオンボーディング内には無い（前進のみ）。全ページに同じ場所のスキップを置き、戻る操作でも前ページへ戻れるようにする（離れる操作に称賛・触覚は付けない）。
- **OB-7 試しの成功の返しを接続ページの先頭へ**：ページ7は「準備できたよ」が見出しで、置けたことへの称賛が薄い。許可カードが出る場合はそちらが主役化してしまう。「置けたよ」という成功の返しを見出し級で先に置き、許可案内はその下に続ける。

## 合格・維持する点
- 1ページ1主張、質問と結果の分離、3択＋逃げ道、質問は1問だけ。
- スリーステップがちょうど3つで、見出しが動詞始まり。
- 試し操作が本物の操作のミニ版（1タップ）で、「あとで試す」で完了扱いになる。
- 権限の案内が体験の後（ページ7）にある。価値の前に許可を求めていない。
- インタラクションが2回（選択＋試し）あり、答えが後段（マッチ・試しのテンプレ）に反映される。
- 全ページに視覚の主役（絵文字・番号箱・カード）がある。総ページ数8は体験直結型として短く、テンポは目安内。

## 未確認
- 4つの達成条件のうち「何のためのアプリか言い直せるか」「使ってみたいか」は人間の体験確認が必要（未実施）。
- ページ数8はスキル目安（10〜15）を下回るが、主張の詰め込みは無く体験直結型として成立しているため、不足とは判定しない（アイデンティティと価値はフックとマッチが兼ねている現状を記録する）。

## v1.4.3 での解消記録（2026-11-17、本人が「必須＋推奨も全部」を選択）

- OB-1 解消：`hapticFeedback(view, strong)` を新設。選択（小）＝軽い触覚＋称賛の文、試しの配置と完了（大）＝成功の触覚（API30+ は CONFIRM）、「次へ」（小）＝軽い触覚。弾みは既存の pressable が担う。称賛は悩み別に3通り（夜／電池／まだわからない）。
- OB-2 解消：進捗を窓ドットに変更（最大5つ、現在を中心に窓がスライド、端は小さいドット、総数を数えさせない）。
- OB-3 解消：マッチページの先頭に、選んだ選択肢の言葉をそのまま映した一文（「夜に音が鳴って困る」——その悩み、受け取ったよ）を置き、その後に宣言＋根拠1つ。
- OB-4 解消：選択後の自動遷移を 400ms → 950ms にし、称賛の文を現在のページで返してから進む。二重タップ防止（遷移中は再選択を受け付けない）も入れた。
- OB-5 解消：最終ページの補足に「始める」を押した先（ホームに置いた自動化が待っている）を具体的に予告。
- OB-6 解消：全ページに同じ場所（下部の行）へ「← もどる」と「スキップ」を常置。物理戻るでも前ページへ戻れる（BackHandler）。離れる操作に称賛・触覚は付けていない。
- OB-7 解消：試しを置いた場合、最終ページの見出しを「置けたよ。最初の自動化、完成」にし、成功の返しを先頭に置いた（許可案内はその下）。
- 検証：ビルドとユニットテストで確認（結果は v1.4.3 納品報告に記載）。触覚の体感と余韻の読み心地は実機待ち。
