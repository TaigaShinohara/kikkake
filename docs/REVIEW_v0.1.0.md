# きっかけ v0.1.0 厳格レビュー（2026-11-16、コード精読による監査）

結論：現状は「触れる試作」であって「任せられる自動化」ではない。実用レベル 3/10。

## 致命的
1. 電池・充電トリガーはアプリを開いている間だけ動く。PowerReceiver は MainActivity の onStart/onStop で動的登録・解除され、Manifest登録レシーバーも常駐サービスもない。アプリを閉じたら自動化が止まる。
2. 通知のランタイム許可を一度も求めていない。POST_NOTIFICATIONS のリクエストコードが存在しないため、targetSdk 36 では初期状態で「通知を出す」が表示されない可能性が高い。
3. Wi-Fi／アプリ起動のきっかけは監視コードが一切なく、永遠に発火しない。なのに選択・保存・有効化できる（UIが嘘をつく）。
4. 「アプリを開く」アクションは固定で端末の設定アプリを開くスタブ。アプリ選択UIがない。

## 重大
5. マナーモード（DNDアクセス許可）と明るさ変更（WRITE_SETTINGS）は特別な許可が必要だが、許可を取りに行く導線がゼロ。テンプレ「22時に静かに」が直撃する。
6. 電池トリガーにしきい値 crossing 検出がなく、BATTERY_CHANGED のたびに連発しうる。アプリ起動直後の sticky broadcast でも即発火する。
7. 再起動で時刻アラームが消える。RECEIVE_BOOT_COMPLETED は宣言のみで再登録コードがない。
8. 1マクロ＝1アクションのみで、複合アクションが作れない（構造的限界）。

## 中程度
9. ライトは点けるだけで消す手段がない。
10. マクロの編集機能がない（作り直しのみ）。
11. 時刻はプリセット4つだけで自由入力できない。
12. アラームが実際に予約されたか確認するUIがない。

## 使える部分
- 作成・保存・一覧・ON/OFF・削除・テンプレ追加、テスト実行（音量・ライト等の権限不要系）は動作する構造で、ビルドとロジックテストで確認済み。
- 時刻アラームはアプリ生存中・未再起動なら発火しうる。

## 直す順番（v0.2 計画）
1. 通知許可リクエストを初回導線に入れる
2. 電池・充電を Manifest レシーバー＋WorkManager 定期チェック等、閉じても動く方式へ
3. 発火しないきっかけは実装するか、UIで「準備中」と明示する
4. アプリを開くアクションにアプリ選択を追加
5. DND／WRITE_SETTINGS の許可導線を追加
6. 電池トリガーの連発防止（crossing 検出）
7. 再起動時のアラーム再登録
